Incident2026.09

GitHub Pages HTTPS가 왜 막혔나

DNS는 정상이었지만 geonu.site용 인증서가 없어 카카오톡 인앱 브라우저에서 차단됐습니다.

GitHub PagesDNSTLSKakaoTalk
확인 과정 보기
증상

HTTP는 열렸지만 HTTPS에서는 서버가 *.github.io 인증서를 제시했고, SAN에 geonu.site가 없어 hostname mismatch가 발생했습니다.

확인 순서
  1. A/CNAME/CAA와 GitHub Pages 연결 상태 확인
  2. 인증서 Subject·SAN·Chain 확인
  3. Pages의 custom certificate와 HTTPS 상태 확인
  4. HTTP/HTTPS 및 www/apex redirect를 각각 분리해 확인
원인과 조치

DNS나 mixed content가 아니라 커스텀 도메인 인증서가 발급되지 않은 상태였습니다. Custom Domain을 제거한 뒤 다시 등록해 인증서 provisioning을 재시작했습니다.

남긴 기준

브라우저가 열린다는 사실만으로 끝내지 않고 DNS → TLS 이름 일치 → redirect 순서로 분리해 확인합니다. 인앱 브라우저는 인증서 우회를 허용하지 않을 수 있습니다.

GuardrailFalse PositiveLLMValidation
확인 과정 보기
증상

응답 내용은 문제가 없는데 검증 단계에서 차단돼 템플릿 응답으로 대체되는 사례가 반복됐습니다.

확인 순서
  1. 실패 케이스를 모아 실제 환각인지 분리
  2. 모델 문제와 판정 로직 문제를 분리

결과와 한계

통과 건수가 166건에서 247건으로 늘었고 LLM 호출은 증가하지 않았습니다. 대신 사용자의 잘못된 전제까지 근거로 인정될 수 있는 Trade-off를 남겼습니다.

Decision Note2026.07

OCR 모델은 어떤 기준으로 골랐나

실물 영수증 13장 × 5개 방식. ‘정확도’ 대신 합계 정합 기준을 먼저 정의하고 비교했습니다.

OCRVisionEvaluationCost
판단 과정 보기
비교 조건

실물 영수증 13장을 5개 방식에 같은 조건으로 통과시키고 다운스케일·재시도·타임아웃을 고정했습니다.

평가 기준

추출한 품목 금액의 합이 영수증 총액과 맞는지를 ‘합계 정합’으로 정의했습니다. 품목별 OCR 정확도와는 다른 지표라는 한계를 함께 적었습니다.

결정

경량 비전 모델은 13장 중 12장에서 합계 정합을 확인했고 실행 오류가 없었습니다. 더 비싼 상위 모델이 유의미하게 낫지 않아 경량 모델을 채택했습니다.

남긴 기준

작은 표본과 지표의 한계를 숨기지 않고, 절대 정확도 주장보다 동일 조건의 상대 비교 결과로 사용합니다.

Decision Note2026.07

저비용 모델이 만점이면 바로 바꿔도 될까

후보 15종·누적 1,750건. 테스트 포화를 의심해 난도를 높이고 판단을 5번 수정했습니다.

LLMBenchmarkLatencyTrade-off
판단 과정 보기
문제

저비용 모델이 기존 모델과 만점 동률이었지만, 모델이 좋아서가 아니라 테스트가 쉬워 차이가 안 보였을 가능성을 의심했습니다.

확인

응답 품질만 보지 않고 비용·응답 지연·Guardrail을 함께 보고, 더 어려운 케이스를 만들어 정보 완전성 차이를 다시 측정했습니다.

결정

저비용 모델의 비용 43%·속도 2배 이점보다 금액 누락 손실이 크다고 보고 즉시 교체를 보류했습니다. 이후 조건이 충족된 기능만 옮겼습니다.

남긴 기준

평가가 포화되면 모델 차이보다 평가셋 난도를 먼저 점검합니다. 입력 케이스풀이 이후 소실돼 완전히 같은 재현은 불가능하다는 한계도 공개합니다.
